# 看得见网速，也能自动选线路

这项更新由两个独立部分组成：SmartTube在加载时显示实际接收速度与可播放缓存；个人网络转换工具可按使用者已经实测的候选生成自动选择组。网速提示帮助观察问题，线路选择才可能改善数据传输，两者都不能承诺任何视频始终流畅。

## 加载时不只有转圈

按 [SmartTube说明](../integrations/smarttube/README.md) 顺序应用两份补丁。加载小提示使用“实时网速”，恢复播放后收起，不长期遮挡视频。大块开发统计需单独开启，日常播放保持关闭。

速度取当前SmartTube应用的接收字节差，每秒更新，包含音视频、缩略图及网络开销；它不是Wi-Fi链路速率、整机所有应用网速或编码码率。KB/MB采用1024进位。缓存足够时播放器会停一下再下载，所以0KB/s不等于断网；看速度时也要看缓存与播放进度。原有视频画质、缓冲大小和账号协议没有被这个补丁改变。

## 先测下载能力，再定自动选择范围

不能只按延迟排名。用本人节点，先检查YouTube连通，再用有界的持续下载筛选，最后在电视上以同片同画质确认。电脑到公共测速端点的速度只能帮助筛选，不能当作电视到视频CDN的结果。不要自动切断正在播放的连接来追逐几毫秒差异。

把个人候选名称写到仓库外的私有JSON，例如：

```json
{
  "preferred": ["本人已实测节点A", "本人已实测节点B"],
  "fallback": ["本人已实测节点A", "本人已实测节点B", "本人备用节点C"]
}
```

```text
python companion/scripts/prepare_network.py --input PRIVATE_INPUT.yaml --output private/tv-auto.yaml --lan YOUR_LAN_CIDR --selection-file PRIVATE_SELECTION.json
```

不传`--selection-file`时仍是原来的普通迁移。传入时生成：

| 入口 | 实际行为 |
|---|---|
| 电视网络 | 默认选自动优选，保留故障回退模式和手动节点入口 |
| 电视自动优选 | 在preferred清单中执行YouTube URL检测，每120秒检查，150ms切换容差，6秒超时 |
| 电视故障回退 | 另一个可选模式：按fallback清单顺序使用可用节点，每60秒检查 |

默认模式只在preferred池内自动选择；它不会在全池失效时自动替用户切换到另一个模式。需要更大范围的保底时，可选择故障回退模式。它不是按实时视频吞吐调度，也不是自动同步网络订阅。

候选名称必须真实存在且不重复；fallback须包含preferred。此自动分组选项要求已经合并成静态`proxies`的配置；有动态providers、sub-rules或依赖旧策略组的链式代理时明确拒绝，先由使用者Agent检查并导出适合自己的静态副本。普通转换仍保留原providers处理方式。

工具移除电脑控制接口、监听、TUN和网卡绑定，限制本地代理监听、保留指定局域网直连；重定向旧代理策略组时保留DIRECT/REJECT与no-resolve。不会修改输入文件或覆盖已有输出。导出的YAML和候选JSON都视为私有资料，不提交GitHub。REALITY short-id保持引号字符串，不让跨语言YAML解析改掉值。

导入电视客户端后，确认新配置已激活、运行在规则模式、“电视网络”确实选中自动组。旧配置保留以便切回。不要把成功导入或VPN图标写成已成功播放。

## 已有实机证据

指定小米私人功能基线上，旧1080p60视频曾缓存耗尽；改用筛选后的线路配置后，用户另选的1080p30视频取得20个有效样本，95.15秒内进度同步前进95.15秒，样本均处于READY。起播5秒后的缓存为32.373–42.977秒，接收速率采样峰值约2.14MB/s；用户反馈当前播放不卡。正常播放截图确认加载小提示和大统计面板均未遮挡。

这不是同一视频、同一画质的严格A/B测试，也不能排除5秒采样之间的极短卡顿；不新增4K60、全天稳定或所有机型通过的结论。源码版保留上游图形，不包含作者个人APK或VPN节点，使用者必须重新完成自己的设备验证。

## 给使用者Agent的排查顺序

1. 分开记录Wi-Fi信号/链路、视频分辨率与帧率、网络引擎、可播放缓存、接收速度和进度。不要把视频码率当实际下载速度。
2. 保留旧网络配置。用同一视频、同一画质对照，每次只改一个变量；节点候选要有实际连通和下载证据。
3. 导入自动分组后核对默认模式与当前选择，再观察缓存是否持续补上；网络检测间隔不会保证所有已有连接立即换路。
4. 首次没有数值、缓冲充足时0网速、持续缺数据、HTTP拒绝、解码能力不足分别处理，不自动降画质或更改账号协议来掩盖原因。
5. ADB offline最多两轮有依据的主机端恢复，仍失败请用户重开调试，不清空授权密钥，不把安装包已生成记为电视已更新。
6. 恢复时先切回原配置；同签名同包名覆盖安装保留数据，不自动卸载或清除登录。

自动检查：`python -m unittest discover -s companion/tests -v`、`python scripts/check_smarttube_patch.py`。Mihomo策略语义见[自动选择](https://wiki.metacubex.one/config/proxy-groups/url-test/)与[故障回退](https://wiki.metacubex.one/config/proxy-groups/fallback/)。
